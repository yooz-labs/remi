## Decided design

Settled, in this order:
1. A deterministic late-poll test in `AnswerOutcomeWireTests`: start the peer, sleep 300 ms (the listener is ready within about 1 ms), then `waitForPort(timeout: .milliseconds(50))` returns a nonzero port; with the old call-anchored implementation or a wrong anchor it would throw. Keep `unstartedListenerTimesOutAndCancels`. Also test the `.ready` without a bound port branch if it can be reached without a mock of production code; if it cannot, say so in the PR body.
2. Diagnosability: record the last NWListener state description under the lock (`.setup`, `.waiting(error)` with the error, `.ready`, `.failed`, `.cancelled`) and put it in `PeerError.startupTimedOut` (for example `startupTimedOut(condition:, lastState:, waitedMilliseconds:)`), in the description text, and in the opt-in trace; update the unstarted test to assert the last state a never-started listener reports.
3. Neutral wording: rename `component` to `condition` and the description to "timed out after N ms waiting for the named condition" (last state: S), with condition phrases such as "NWListener ready with a bound port", "the peer to reject input", "the connection to end"; the readiness string is one internal constant used by the code, the trace and the test.
4. Sibling waits: `waitForConnectionReady`, `waitForRejection`, `waitForConnectionEnd`, `stop()`'s waits get the same pattern as `waitForPort` (record the event's instant in the NWConnection state handler and accept a late poll when the event preceded the deadline), with consistent generous bounds; in `ImageIngressSocketTests` raise the hello, unsupported and sessions loop deadlines (the 5 s ones) to the same generous bound and say why in a comment. Use `clock.now` everywhere in the file (no mixed `ContinuousClock.now`).
5. Docs: a `///` comment on `waitForPort` and the sibling waits: the deadline runs from the start request (or from the call if never started), the 30 s default is a generous bound above the 5 s that expired on hosted runners and not a measured latency (see #1634), a listener ready before the deadline is accepted even if the poll resumed late, and the trace environment variable name.
6. Tidy: `snapshot()` keeps the Instants out of the tuple (a small private accessor read under one lock); reuse `startupRequestedAtOrNow()` in the state-handler branches.
7. PR body: say that the local 30/30 and 10/10 runs are a no-regression check, not a reproduction (the old code was never shown to fail locally); record the machine load average (`uptime`) during the loaded runs in the evidence folder; say that the cause is bounded to "the first wait expired after 5 s on a slow hosted runner" and not proven; list what changed in this round.
