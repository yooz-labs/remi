## Goal

A `Level2Controller` that the hub can own (not yet wired: L2-HUB does that) arms, starts (automatically at the first real work while armed, Q1 (b), or explicitly), extends, stops and reverts level 2 exactly as the L2-POL reducer decides, persists the arming latch so no hub ever starts a second automatic period by itself, writes the lease before it turns sleep off, reads every guard on a heartbeat, blanks the display on a lid close, reverts on shutdown (async and synchronous paths) and at startup reverts a lease it does not own; the only code that can run `sudo` is a `SudoPmsetSwitch` built from W1's constants, and every test drives it through a recording stand-in at that root boundary, never through `sudo`.

## Decided design

Settled:

1. **The switch** (`level2-switch.ts`): interface `Level2Switch { enable(); disable(); disableSync(); displaySleepNow() }`, each returning `{ ok: true }` or `{ ok: false, reason }` with `reason` one of `revert-not-permitted`, `sudo-refused` (nonzero exit), `timeout`, `spawn-failed`, `read-back-mismatch`, `read-back-unknown`.
   `SudoPmsetSwitch` runs `[SUDO_PATH, ...sudoArgv(DISABLESLEEP_ON)]` or `[SUDO_PATH, ...sudoArgv(DISABLESLEEP_OFF)]` with `shell: false`, `stdio: 'ignore'`, environment `{ LC_ALL: 'C', PATH: '/usr/bin:/bin:/usr/sbin:/sbin' }`, a 5 s deadline (SIGKILL after), then reads `SleepDisabled` back with G1's `readRootDomain`: enable must read `yes` (on `no` or unknown it runs the disable argv once and reports the mismatch), disable must read `no`.
   Before every enable, it runs `[SUDO_PATH, ...sudoListArgv(DISABLESLEEP_OFF)]` and then `[SUDO_PATH, ...sudoListArgv(DISABLESLEEP_ON)]` (sudo only lists; nothing runs as root); a nonzero exit of the first refuses with `revert-not-permitted`, of the second with `sudo-refused`, and the enable does not run: sleep is never turned off unless the revert is allowed.
   `disableSync` does the same as `disable` with `spawnSync` and a 3 s timeout (for the `exit` listener).
   `displaySleepNow` runs `[PMSET_PATH, ...DISPLAYSLEEPNOW]` with no `sudo` (ADR 0050 line 129: UNVERIFIED that it needs no root; OG-L2 checks it).
   The constructor takes optional `spawnRoot` and `spawnRootSync` (default: the real spawns above) and `readRootDomain` (default G1's): this is the root-boundary substitute ADR 0050 slice 3 allows, and tests use only that.
   Nothing outside `level2-switch.ts` spawns `SUDO_PATH`.
2. **Readers added**: `readings/screen-lock.ts` implements G0's settled source and parse rule exactly (only "immediately" is `on`; everything else, including a delay, a failure or a "not settled" G0, is `off` or `unknown` as the note says); `readings/launchd.ts` reads `launchctl print gui/UID/com.yooz.remi.keep-awake-watchdog` (UID from `process.getuid()`): exit 0 is `loaded`, the not-found exit code observed on this Mac is `missing`, anything else `unknown`.
   `runReading` allows `LAUNCHCTL_PATH` only with first argument exactly `print`, and G0's executable only with G0's exact arguments; a source that answers on stderr is read with G1's `captureStderr`.
   The watchdog reading is `loaded` only when `launchctl print` exits 0, the property list `~/Library/LaunchAgents/com.yooz.remi.keep-awake-watchdog.plist` names this remi home's `keep-awake/watchdog.sh` as its second program argument (`plutil -extract ProgramArguments.1 raw -o - PLIST`, which `runReading` allows for `PLUTIL_PATH` with exactly those arguments and that path), and that script's bytes equal `buildWatchdogScript({ remiHome })` of this build; loaded with either check failing is `mismatch`; not loaded is `missing`.
   One label serves one remi home per user; a watchdog installed from another home, deleted, or written by another build is `mismatch`.
3. **Readings aggregate** (`level2-readings.ts`): `Level2Readings` with `read(remiPids)` returning L2-POL's inputs: battery (G2), thermal and root domain (G1), the foreign holders (G1's assertions classified by L2-POL's `classifyForeignHolders` with the settings' ignore list), password on wake, watchdog; all readers run in parallel, each already bounded.
   `MacLevel2Readings` is the real implementation; tests use the same class over fixture text (the real parsers, a scenario choosing which committed capture each reader returns), so no parser or rule is replaced.
4. **Census** (`level2-census.ts`): `live` is the number of `listLive()` entries.
   An entry is working when its `status-PORT.json` (read with a 64 KiB cap) has `awakeHold: true` (level 1's own verdict, published by L2-HUB, so the idle revert inherits the question cap, the stuck bound and the open-turn rule); when the field is absent (an older session daemon, or `level1 = false`), it is working when its `sessionStatus` is `thinking`, `executing` or `waiting`, or it has a pending question whose `createdAt` is within `question_hold_minutes`; unreadable counts as not working.
   `remiPids` is the hub's pid, every entry's `pid` and `claudeChildPid`, and all their descendants, from one `ps -A -o pid=,ppid=` read (`runReading` allows `PS_PATH` with exactly those arguments), so an agent's grandchildren are remi's; a shared process that is not a descendant (for example Codex's app-server) stays foreign, a narrowing of ADR 0050's "remi's process tree" stated in the docs.
5. **The controller** (`level2-controller.ts`), constructed with settings, `remiHome`, `hubPid`, a `Level2Switch`, a `Level2Readings`, a census function, a clock (`now()` monotonic milliseconds, `wallNow()` epoch seconds, `setTimer`, `clearTimer`, the `AwakeClock` shape of `awake-session.ts:22-26` plus `wallNow`), a log function and an optional `onStatus` callback.
   Operations are serialized (one at a time).
   Methods:
   - `reconcileAtStartup()`: no lease, nothing; a lease (valid or not; a new hub never owns an earlier lease) with the flag `yes` or unreadable: `disable()`, then delete the lease only when the flag reads `no`; with the flag `no`: delete the lease, no switch call.
     It never turns level 2 on (ADR 0050 line 98), and it writes the latch whenever it found a lease, so the hub comes up `disarmed`.
   - The latch (`level2-latch.ts`): `REMIHOME/keep-awake/latch.json`, schema `{ version: 1, at, origin }` (`at` epoch seconds, `origin` `automatic` or `explicit`), directory 0700, file 0600, written through a temporary file, `fsync` and `rename`; `readLatch` returns `none`, `valid` or `invalid`, and an invalid, unreadable or foreign-owned file counts as latched (fail closed: no automatic start).
     The controller builds its initial state with L2-POL's `initialLevel2State(settings, latched)` after `reconcileAtStartup()`.
   - `start(hours?)`, `arm()`, `extend(hours)`, `stop()`, `status()`: through the L2-POL reducer; `unlatch` removes the latch file, and a removal failure keeps the state `disarmed` and is reported.
     On `latch`: write the latch file; a failure is `enable-failed` with `lease-write-failed` and no lease and no switch call.
     On `enable` (always after `latch`): write the lease next (W1's `writeLease`: `hubPid`, `hubStartTime` from `processStartTime(hubPid)`, `startedAt` and `heartbeatAt` now, `expiresAt` from the reducer's expiry converted to wall time, `staleSeconds` from `lease_stale_seconds`, `revertBatteryPercent` from the settings); a failed write is `enable-failed` with `lease-write-failed` and no switch call; then `switch.enable()`; a failure deletes the lease and is `enable-failed` with `switch-failed`.
   - While `armed`, a census-only tick every `heartbeat_seconds` (file reads, no spawn) feeds `census`; a `read-for-start` effect makes the controller take every reading once and feed `attempt`; nothing runs while `disabled` or `disarmed`.
   - Heartbeat every `heartbeat_seconds` while `starting`, `on` or `reverting`: rewrite the whole lease from the controller's memory (a new `heartbeatAt`, and `expiresAt` after an extend) atomically, a failure being `heartbeat-failed`; read; step `beat`; apply effects: `disable` runs `switch.disable()` and deletes the lease on success, keeps it on failure (the watchdog retries too); `forget` deletes the lease with no switch call; `notify` logs one line with process names only.
   - Lid: when the root domain's `clamshell` changes to `closed` while `on`, call `displaySleepNow()` once; again only after it was seen `open`.
   - `shutdown()` (for the hub's async cleanup, at most 3 s) and `shutdownSync()` (for the `exit` listener): when `starting`, `on` or `reverting`, disable and delete the lease on success (the latch stays); stop the timers.
   - `status()` returns `{ level2: 'disabled' | 'armed' | 'disarmed' | 'starting' | 'on' | 'reverting', origin: 'automatic' | 'explicit' | null, allowed: settings.level2, reason, startedAt, expiresAt, capAt (ISO 8601 UTC), battery: { source, percent } or the reading's kind, thermal, sleepDisabled, foreignHolders: process names, lastRefusal, lastRevert }`; `onStatus` fires on each change.
   - Logs: prefix `[Awake2]`, one line per transition (armed at boot, start with its origin, an automatic refusal only when its reason changes, an explicit refusal with reason, revert with reason, foreign-holder notice, lid display sleep, reconcile, switch failure), never per heartbeat, never lease contents beyond reasons, never assertion names; a start with `require_password_on_wake = false` logs a warning that the Mac stays awake and unlocked with the lid closed (ADR 0050 table: "logged loudly").
6. **Fixtures**: redacted OG-CAP captures for the Safari-video and call states feed the classifier through G1's real parser; the laptop `pmset -g batt` captures replace W1's assumed laptop line in `watchdog-script.test.ts`.
The implementer may choose: internal structure of the controller, timer handling details within the clock interface, test names, scenario helper names.
