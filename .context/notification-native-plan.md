# Native paired-device notifications (#1680)

The owner approved automatic registration after pairing and notification permission, active renewal and explicit Continue/Revoke after 30 days inactive. This phase depends on #1683 and keeps the foreground route profile, addresses, identity, aliases and manual layer selection unchanged.

Mirror the strict notification-host wire contract and correlate each response on the current authenticated direct connection. Derive the machine key from that connection, never from the response. Use a separate notification relay route in the existing identity-generation SQLite ledger; it cannot restore a foreground Relay route. Existing full relay trust remains independent. A short-lived broker-owned encrypted channel registers the OS token and recipient key, then closes; it does not browse sessions or send application Hello. Preserve key/identity generation checks across every await. Persist Revoke intent so automatic registration cannot immediately undo it.

Foreground activation and a bounded periodic check register permitted paired machines and renew current subscriptions. Expired state is visible and does not re-register without Continue. Registration errors remain visible per host. Signed APNs environment comes from actual entitlements; no token is persisted in preferences or sent on the direct socket. Revoke and Forget invalidate local notification trust before late callbacks can reinstall it. OS permission revocation suppresses further registration and unregisters where reachable.

New native full-relay clients explicitly send `renewExpired: false` for automatic registration and `true` only after Continue. The host respects an explicit false for both scopes; omission preserves older full-relay clients' behavior. Notification-only clients never auto-revive when the field is absent. This small host compatibility correction is verified with the real encrypted HubRelay alongside the native phase.

Use real SQLite/Keychain test stores, strict golden contract fixtures and owned direct/relay servers. Cover migration and full-versus-notification trust, stale connection/identity/Forget during registration, token rollover, expiry consent and durable opt-out. Run Swift package tests, unsigned Mac/iPhone builds and rendered UI checks. Signed app/NSE decryption, deployed APNs receipt and physical iPhone/Watch presentation remain separate owner acceptance.
